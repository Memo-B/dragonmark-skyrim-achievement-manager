# Dragonmark visual system and runtime artwork

## Direction

Cold blue charcoal, frost-white text, restrained antique metal, original mountain silhouettes and angular engraved corners give Dragonmark a Nordic atmosphere. The independent dragon/check emblem remains the product identity. Cinzel supplies display headings; Segoe UI supplies readable body text. No Bethesda logo, game font, texture, music or extracted game file is bundled.

The WPF design system styles buttons, press/hover/focus feedback, checkboxes, combo menus, text fields, lists, scrollbars, tooltips, progress, confirmation, results and notices. The principal pages share the same material, spacing and typography. Achievement entries retain description, API identifier, recorded date, status, available rarity and selection; each locked entry has its own confirmed preview action.

Original decorative geometry lives in `VisualDesign.cs`; brand SVG/PNG/ICO sources are regenerated by `scripts/Generate-Branding.ps1`. Public demo illustrations are original fictional artwork, explicitly labelled, and are never substituted for available Steam icons in live mode.

## Authentic Steam artwork

The live provider uses `GetAchievementDisplayAttribute`, `GetAchievementAndUnlockTime` / `GetUserAchievementAndUnlockTime`, `GetAchievementIcon`, `GetImageSize`, `GetImageRGBA` and `UserAchievementIconFetched_t`.

Callback identity includes App ID, API identifier and achieved/unachieved variant. Decoded RGBA pixels are cached in memory by identifier and state. WPF converts the channel layout to BGRA without changing the artwork's colors, opacity or aspect ratio. Only the frame reflects selection, rarity and unlocked state.

`GetAchievementIcon` returns the current variant; it is not an arbitrary locked/unlocked image selector. The app uses a matching cached variant or requests the current one only when it matches the enumerated state. It never changes an achievement to obtain an image. Missing artwork remains visibly unavailable. Native callbacks can fill it later, and the UI performs a second bounded read pass. A confirmed action pauses/cancels background icon reads before entering the serialized provider, so artwork cannot race a write.

Read-only probe on **2026-11-09**: **75/75 icons loaded** from the authenticated Skyrim context, including icons for both currently locked and currently unlocked entries. No SetAchievement, ClearAchievement or StoreStats call occurred. This confirms icon retrieval on that installation, not live unlock persistence or every possible variant of every icon.

References: [Valve achievement APIs](https://partner.steamgames.com/doc/api/ISteamUserStats#GetAchievementIcon) and [Valve image APIs](https://partner.steamgames.com/doc/api/ISteamUtils#GetImageRGBA). Public screenshots use the isolated demo so personal history and proprietary runtime artwork are not distributed as project assets.

## Optional local artwork

Settings → **Choose local image** accepts a user-selected local PNG/JPEG up to 16 MB and 16384 pixels per side. Decoding is scaled within a 1920 × 1080 envelope while preserving aspect ratio. The image is subdued behind controls; authentic achievement artwork is unaffected. Only the path is retained in local settings. It is not uploaded, copied into exports, committed or included in packages. Network paths are rejected.

**Restore original mountains** removes the preference. A missing/invalid file reports a local error and keeps the application usable. An installed Skyrim license does not by itself grant redistribution rights: no automatic extraction or scanning of game archives is implemented. Local installation is checked through Steam only for diagnostics.

## Motion and accessibility

Page/search/filter reveals and dialog openings use short 160 ms fades. Busy feedback uses a single restrained opacity pulse; there is no continuous animated background, particle system or rendering loop. Buttons and selected cards provide immediate contrast and pressed/focus states.

**Reduce motion** disables fades and the pulse. Windows `ClientAreaAnimation` preferences are also respected, including changes while running. An operation remains visible as text/static progress when motion is disabled. No celebration claims success before verification. Cancellation is available for reads and before staging, then disabled while persistence evidence is being resolved.

Ctrl+F focuses search, F5 refreshes, standard Tab/arrow navigation is retained, and confirmation defaults to **Keep unchanged**. Final physical keyboard/screen-reader testing is still pending: the Windows automation helper could read controls but rejected clicks with `coordinate input geometry is unavailable` during this pass.

## Captures and resolution checks

The [seven public screenshots](../assets/screenshots/README.md) come from the actual compiled `1.0.0` WPF application and an isolated demo profile. The capture path cannot connect to Steam and never confirms a write. Additional local QA captures cover presets, history, About, locked/unlocked, empty search, 1100 × 740 window layout and a 150% raster render. The measured WPF capture environment was 96 DPI; a separate real 150% monitor/per-monitor DPI and full screen-reader pass remain unverified. Raster scaling is not claimed to replace those tests.

Version 1.0.0 constrains window size to the monitor work area and provides scrolling for content that cannot fit. WPF integration tests verify bottom-action reachability against logical work areas corresponding to 100/125/150/200% scaling, default Enter/Escape cancellation, explicit confirmation and focus traversal. Additional QA captures show these constrained layouts; these do not establish physical per-monitor or screen-reader coverage.
